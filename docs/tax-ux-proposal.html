세금 화면 재설계 — 프로세스 제안

현재 화면은 설정 7개를 통과해야 숫자가 나오는 계산기입니다. 사용자의 일은 계산이 아니라 “내 숫자를 믿을 수 있는지 판단하는 것”입니다.
아래 모든 금액·문구·건수는 lib/tax 엔진을 실제로 실행한 출력입니다(내 지갑 이벤트 14건 / 제외 6건 기준). 지어낸 숫자 없음.

① 답이 먼저

진입 즉시 거주국·내 지갑 기준 숫자 하나. 설정 0개.

② 신뢰도가 두 번째

“이 숫자에서 흔들리는 것”을 영향도 순으로. 각 항목이 고치러 가는 링크.

③ 정밀화는 필요한 것만

requiredInputs가 있는 입력만 노출. 인도는 0개.

④ 비교는 별도 모드

compareRuleSets를 뚫어 나란히. 라디오 버튼 아님.

흐름 비교

현재 — 답까지 7단계

국가 12개 중 선택→ 이벤트 출처→ 과세연도→ 한계세율→ 지갑 외 소득→ 사업자→ 디파이 소유권→ 숫자

제안 — 답이 0단계

숫자→ 흔들리는 것→ 필요한 입력만 (0~2개)→ 비교 (선택)

거주국은 DID 클레임에 이미 있음(session.countryCode) · 출처는 “내 지갑”이 기본 · 과세연도는 현재 연도

먼저, 아주 쉽게

아래 기술적인 얘기를 읽기 전에 이것만 이해하면 됩니다.

“이 거래 세금 얼마야?”

답이 없는 질문입니다. 세금은 1년 통째로 계산되기 때문입니다.

1 오래 갖고 있으면 세금이 0이 됩니다

독일은 1년 넘게 보유한 코인을 팔면 아무리 벌어도 세금 0원입니다.
비트코인 팔아서 4,965유로를 벌었는데 세금은 0원. 그럼 “이 거래 세금”은 0원인가요?

2 손해 본 거래가 다른 거래 세금을 깎습니다

A에서 100 벌고 B에서 100 잃으면 합쳐서 0 → 세금 0원.
그럼 A의 세금은? B의 세금은? 나눌 방법이 없습니다. 게다가 인도는 손해를 아예 안 쳐줍니다.

3 문턱이 있습니다

독일은 1년 수익이 1,000유로 미만이면 세금 0원, 1,001유로면 전액 과세입니다.
마지막에 한 작은 거래 하나가 앞의 모든 거래를 과세로 바꿔버립니다.

실제로 계산기를 돌려봤더니

예시 지갑의 독일 기준 세금 1,015유로가 어디서 나왔는지 거래별로 확인해봤습니다.

  • 판 거래 5개 → 세금 기여가 전부 0원. 4,965유로를 번 매도조차 0원입니다.
  • 세금을 만든 건 스테이킹·에어드랍으로 받은 것 4개였습니다.
  • 심지어 비트코인 “산” 기록을 지우면 세금이 7,914유로 늘어납니다. 산 가격이 사라지면 번 돈이 그만큼 커지니까요.

거래 목록에 “세금” 칸을 만들었으면 전부 0원으로 보이고, 그럼 1,015유로가 어디서 나온 건지 화면이 설명하지 못합니다.

❌ 월별 세금도 안 됩니다

영국은 세금 1년이 4월 6일 ~ 다음 해 4월 5일이고 호주는 7월 ~ 6월입니다. 월로 나눈 숫자는 어느 나라 신고서에도 안 맞습니다.

✅ 그래서 이렇게 보여줍니다

총액은 1년치 하나만. 거래 목록에는 세금 대신 “과세 / 비과세 / 손실” 도장만 찍습니다. 거래별 금액은 세금이 아니라 손익입니다.

덤 ① “이 거래가 없었으면 얼마 달라졌나”

세금을 억지로 나누는 대신, 빼고 다시 계산해서 차이를 보여줍니다. 이게 “건당 세금”의 진짜 버전입니다.

덤 ② “언제까지 갖고 있으면 세금 0원 되나”

“솔라나를 320일만 더 갖고 있으면 세금 0원” — 유일하게 사용자 행동을 바꾸는 정보입니다.

표시 단위 — 건당? 월별? 기간?

이건 취향 문제가 아닙니다. 아래는 독일 룰셋으로 실제 계산한 부담 €1,015.44를 이벤트별 한계 기여도(해당 이벤트를 뺐을 때의 총액 차이)로 분해한 것입니다.

매도 5건의 세금 기여가 전부 0원입니다. 차익 €4,965짜리 매도의 세금이 0원이고, 실제 €1,015.44는 전부 스테이킹·에어드랍에서 나옵니다. 매수는 기여가 음수입니다.

거래 목록에 “세액” 컬럼을 그렸다면 이 지갑은 전부 0원으로 보이고, €1,015.44가 어디서 왔는지 화면이 설명하지 못합니다. 건당 세액은 직관과 반대이거나 아예 존재하지 않습니다.

① 거래 1건 ≠ 손익 1건

FIFO/LIFO는 lot 단위로 매칭됩니다(for (const match of consumption.matches)). 매도 1건이 손익 행 여러 개로 쪼개지고, 같은 매도 안에 과세분과 비과세분이 섞일 수 있습니다.

② 취득원가가 경로 의존

앞 거래를 바꾸면 뒤 거래의 손익이 전부 바뀝니다. 위 표에서 매수 1건의 기여가 −7,914.50인 게 그 증거입니다.

③ 상계·공제가 기간 단위

인도 §115BBH(2)는 손실 상계 자체가 불가라 손실 건의 기여가 정확히 0입니다. 독일은 상계·이월. 같은 거래의 “세금”이 나라마다 정의부터 다릅니다.

④ 임계가 비선형 계단

독일 Freigrenze €1,000은 차감형이 아니라 초과 시 전액 과세. 프랑스는 양도가액 총액 바닥. 마지막 1건이 앞의 전부를 과세로 뒤집으므로 건당 배분이 원리적으로 불가능합니다.

월별 세액도 존재하지 않습니다

과세기간이 월 경계와 무관합니다 — 영국 4/6~4/5, 호주 7/1~6/30(taxPeriod). 연 단위 임계·공제를 월에 배분할 방법도 없습니다. 월별 합계는 어느 나라 신고 서식에도 대응하지 않는 숫자입니다.

건별 손익조차 나라마다 다릅니다

같은 dsp-eth-09의 손익 — 독일 2,967.50 / 인도 3,000(수수료 불인정) / 영국 2,910.10(Section 104 평균). 영국은 보유일수가 null이고 어떤 행은 −10일(30일 규칙)입니다.

결론 — 3계층 + 파생 2개

세액은 기간에만 존재합니다. 건별에는 사실과 판정만 존재합니다.

L1기간 총액 — 답

과세기간 1개, 숫자 1개. 유일하게 신고 서식에 대응하는 값.

L2판정 그룹 — 왜

과세 / 비과세 / 소득 / 상계·이월 / 제외. 룰셋이 만든 분기. 각 그룹에 건수와 합계.

L3건별 사실 — 근거

손익·취득일·보유일수·판정 라벨. 세액 컬럼 없음. 거래 목록의 한 열로 들어감.

파생한계 기여도

“이 거래를 빼면 총액이 얼마 바뀌나”. 사용자가 “건당 세금”으로 원했던 것의 정직한 버전.

파생시간축

월별 세액이 아니라 임계까지 얼마 + 보유기간 며칠 남았나. 유일하게 행동을 바꾸는 시간 정보.
