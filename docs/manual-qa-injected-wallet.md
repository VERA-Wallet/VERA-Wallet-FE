# 실제 injected 지갑 수동 QA 체크리스트 (AC2 보완)

자동화(Playwright synthetic EIP-1193 fixture)는 서명 왕복과 금지 RPC 부재까지 검증하지만,
실제 확장 프로그램(MetaMask 등)의 UI 승인 흐름은 재현할 수 없다. 릴리스 전 아래 절차를 사람이 1회 수행한다.

## 준비
- `pnpm dev` (기본 3000 포트) 실행, 브라우저에 MetaMask 설치·테스트 계정 1개 이상 준비.
- 테스트 계정은 자산이 없어도 된다(트랜잭션을 보내지 않는다).

## 체크리스트

| # | 절차 | 기대 결과 | 통과 |
|---|------|-----------|------|
| 1 | `/login`에서 거주국 `KR` 선택 → QR/딥링크 제시 → 제시 완료 | 거주국 클레임 확인 문구와 룰셋 배지(`KR …`)가 노출된다 | ☐ |
| 2 | `지갑 연결로 계속` 클릭 | `/connect-wallet`으로 이동하고 `mock 데이터` 배지가 보인다 | ☐ |
| 3 | `지갑 연결하기` 클릭 | MetaMask **연결(Connect)** 팝업만 뜬다. 트랜잭션 승인 팝업이 **뜨지 않는다** | ☐ |
| 4 | 연결 승인 후 `SIWE 서명으로 계속` 클릭 | MetaMask **서명(Sign-in request)** 팝업이 뜬다. 가스비 표시가 없다 | ☐ |
| 5 | 서명 승인 | `/dashboard`로 이동하고 요약/거래 리스트가 채워진다 | ☐ |
| 6 | 서명 거절(3~4단계 재시도 후 Reject) | 화면에 한국어 오류 안내가 뜨고 세션이 생성되지 않는다 | ☐ |
| 7 | 대시보드 상태에서 MetaMask 계정 전환 | 자동으로 로그아웃되어 `/login`으로 이동한다 | ☐ |
| 8 | 다시 로그인 후 대시보드에서 MetaMask 네트워크 전환 | 자동으로 로그아웃되어 `/login`으로 이동한다 | ☐ |
| 9 | 전체 과정 동안 MetaMask 활동 로그 확인 | `eth_sendTransaction` / `eth_signTransaction` / `eth_sendRawTransaction` 호출이 **0건** | ☐ |
| 10 | 모든 화면 하단 확인 | 면책 문구가 스크롤과 무관하게 하단에 고정 노출된다 | ☐ |

## 실패 시
관측한 팝업 종류·오류 문구·MetaMask 활동 로그를 첨부해 이슈로 기록한다.
7·8·9번 실패는 스펙 금지사항 위반이므로 릴리스 차단 사유다.
